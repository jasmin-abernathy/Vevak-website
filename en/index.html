The idea

A digital fallback that does less, but makes its limits understandable.

Many location-sharing tools depend on Internet access, remote accounts and tracking infrastructure. VeVak explores a different route: use SMS and capabilities already present in Android, with a deliberately limited scope.

How it works

Four steps. No magic.

The current VeVak core follows a small, bounded path.

  1. 01

    You choose the contact

    A trusted phone number and an exact request phrase are configured directly on your phone.

  2. 02

    The SMS arrives

    VeVak locally checks the sender, phrase and request rate before taking action.

  3. 03

    A location is requested

    A sufficiently recent cached location is preferred. Otherwise, a bounded one-time lookup may be attempted.

  4. 04

    A reply is sent

    If Android, the mobile network and location availability allow it, VeVak replies to the authorised contact by SMS.

Principles

Privacy is not an option buried in settings.

The project starts from a simple idea: the best sensitive data is often the data you never collect.

Local by default

The core does not require a VeVak account, VeVak server or permanent Internet connection.

No permanent tracking

Location is requested on demand. The current core does not perform periodic location tracking.

No ads, no trackers

No advertising SDKs, telemetry or user profiling.

FOSS first

The free/open-source variant remains canonical. Google components are isolated in the dedicated Play flavor.

!

Important limitations

VeVak is not an emergency service.

The core does not require Internet access, but it still depends on mobile-network/SMS availability, Android permissions, location availability and the phone's background restrictions. It cannot guarantee that an SMS will arrive or that a location will be obtained.

In an emergency, use official emergency services and your phone's built-in emergency features.

Project status

Make it reliable before making it bigger.

The SMS/location engine already exists. The current priority is real-world robustness.

Now · P0

Stabilisation

  • installable and reproducible builds;
  • real SMS → location → reply testing;
  • dual-SIM / eSIM behaviour;
  • screen-off and battery restrictions;
  • accessibility and actionable diagnostics.
